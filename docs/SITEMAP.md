# OptiCore 웹사이트 구조 (IA)

## 핵심 아이디어

일반적인 SI 회사 사이트: `회사소개 / 사업분야 / 포트폴리오 / 고객센터`.
OptiCore 사이트: **스크롤할수록 회사의 코어에 가까워지는 렌즈.** 메뉴도 "우리가 누구인가"가 아니라 "고객이 무엇을 하게 되는가" 순서로 짠다.

세 가지 차별점:
1. **초점 맞추기 히어로** — 고객 회사의 흩어진 업무(엑셀, 카톡 결재…)가 초점이 맞으며 시스템 모듈로 정렬된다. 다이얼로 직접 조작 가능.
2. **방법론 = 상태 머신** — `SCAN → FOCUS → BUILD → RUN → SCAN`. 각 상태에 "다음으로 가는 조건"을 공개.
3. **에이전트 입구** — 사람용 페이지와 함께 `llms.txt`, 상태 API, 진단 API를 제공. AX 회사가 자기 사이트부터 AX로 만든다.

## 사이트맵

```
/                       홈 (렌즈 벤치: ∞ → 0.3m)
├─ /method              일하는 순서 (상태 머신 상세, 단계별 산출물·기간·전이 조건)
├─ /lenses              서비스
│   ├─ /lenses/si       시스템 통합
│   ├─ /lenses/erp      ERP 구축 (오픈소스 vs 패키지 vs 자체개발 비교표 포함)
│   ├─ /lenses/ax       AI 전환 (에이전트, 사람 승인 단계, MCP)
│   └─ /lenses/saas     구독형 모듈
├─ /field-log           사례 (Before → After 상태 다이어그램 형식, 고객 동의 받은 것만)
│   └─ /field-log/[slug]
├─ /principles          일하는 원칙 6가지 (엔지니어·에이전트 공통)
├─ /lab                 기술 노트 (블로그: 오픈소스 비교, CI 감사 리포트 공개 등)
├─ /diagnose            진단 시작 (문의 양식 대신 3문항 진단 → 추천 시작 상태)
├─ /company             회사 정보, 팀, 채용, 법인 정보
└─ 에이전트 입구 (사람 메뉴에는 숨김, 링크/헤더로 노출)
    ├─ /llms.txt              AI가 읽는 회사 요약
    ├─ /llms-full.txt         서비스·방법론 전체 텍스트
    ├─ /api/diagnose          POST: 진단 문항 → 추천 상태 (JSON)
    └─ /api/project-state     GET: 고객 프로젝트 상태 (인증 필요, 고객 포털과 공유)
```

## 홈 섹션 순서 (초점거리)

| 거리 | 섹션 | 페이지의 일 |
|---|---|---|
| ∞ | 히어로 | "흐릿한 업무를 선명한 시스템으로" + 초점 다이얼 데모 |
| 5 m | 일하는 순서 | 4개 상태, 클릭하면 산출물과 전이 조건 |
| 2 m | 서비스 (네 개의 렌즈) | SI · ERP · AX · SaaS, "이럴 때" 문장으로 자기 진단 유도 |
| 1 m | 원칙 | 6가지 원칙, 버그 분류 점수 계산기 |
| 0.5 m | 에이전트 입구 | llms.txt / 상태 API 미리보기 |
| 0.3 m | 진단 | 3문항 → 추천 시작 상태 + 보낼 내용 복사 |

## 고객 포털 (2단계)

계약 고객 전용 `/portal`: 프로젝트 상태(SCAN/FOCUS/BUILD/RUN), 이번 스프린트 시연 영상, 이슈 목록(빈도×심각도 점수 포함), 월간 운영 리포트. 사이트의 `/api/project-state`와 같은 데이터를 쓴다.

## 기술 스택 제안

- **Astro** (정적 사이트 + 콘텐츠 컬렉션으로 사례/기술노트 관리, 빠름, SEO 유리)
- 진단 API·포털은 필요해질 때 별도 서비스로 (지금은 정적 페이지 + 복사 방식)
