# OptiCore 브랜드 아이덴티티 (CI)

> **메모 (2026-11): 마케팅 회사로 포지션 변경, 웹 문구는 이 지침보다 web/src/data 우선.**

> 한 줄 요약: **흩어진 업무(Optic, 빛)를 하나의 초점(Core)으로 모은다.**
> 비주얼 언어는 "렌즈"다. 흐릿함 → 선명함, 흩어짐 → 정렬, 색수차 → 단일 초점.

---

## 0. 포지셔닝과 고객

- **우리는 누구인가**: AX(AI 전환) 전문 구축팀. ERP·시스템 통합·구독형 모듈은 "AI가 일할 바탕"을 만드는 일로 설명한다.
- **핵심 주장**: AI는 흐릿한 업무를 대신해 주지 못한다. 먼저 업무를 선명하게 만들고, 그다음 AI에게 맡긴다.
- **고객(페르소나)**: 직원 30~200명 회사의 대표, 운영 총괄, 실무 팀장.
  - 대표: "AI를 도입하라는데 어디서부터 해야 할지 모르겠다."
  - 운영 총괄: "챗봇은 쓰는데 회사 업무는 그대로다."
  - 실무 팀장: "AI가 틀리면 누가 책임지나."
- **우리 방식 (사이트에서 직접 보여 주는 것)**
  1. 빈도 × 효과 점수로 AI에 맡길 업무를 고른다 (상위 3개가 1차 과제).
  2. 거래처에 나가는 문서, 돈이 움직이는 일에는 사람 승인 단계를 둔다.
  3. 시범 에이전트로 효과를 먼저 숫자로 잰다.

## 1. 이름의 뜻

| 요소 | 의미 | 브랜드에서 쓰는 방식 |
|---|---|---|
| **Opti** (Optic / Optimal) | 렌즈, 보는 방식, 최적화 | 고객의 업무를 "다른 렌즈"로 들여다본다 |
| **Core** | 핵심, 코어 시스템, 칩 | ERP·데이터·에이전트가 모이는 회사의 중심 |

- 국문: **옵티코어** / 법인명: **주식회사 옵티코어**
- 영문: **OptiCore** (워드마크는 소문자 `opticore`)
- 태그라인: **흐릿한 업무를, 선명한 시스템으로.**
- 짧은 시그니처: `focus → core`

- 대표: 김건영

## 2. 심볼

![symbol](logo-symbol.svg)

- **원(링) = 렌즈(Optic)**, **안쪽 사각형 = 코어(Core, 칩/시스템)**.
- 바깥에서 보면 알파벳 `O`, 안을 보면 칩. 두 사업 축(컨설팅적인 '보는 일' + 엔지니어링 '만드는 일')을 한 기호에 담음.
- 사각형만 코어 코발트, 링은 본문색. **색은 코어에만 쓴다**는 브랜드 규칙이 심볼에서 시작된다.

### 사용 규칙
- 최소 크기: 16px(디지털) / 5mm(인쇄)
- 여백: 링 두께(3/24)의 2배 이상 사방 확보
- 금지: 링에 색 넣기, 사각형 회전, 그라데이션, 그림자, 사각형을 원으로 바꾸기

### 워드마크
![wordmark](logo-wordmark.svg)
- 심볼 + `opticore` (Bricolage Grotesque SemiBold, 자간 -2%)
- 국문 병기 시: 워드마크 아래 `옵티코어` (IBM Plex Sans KR Medium)

## 3. 컬러

**원칙: 화면 대부분은 무채색 유리색. 코어 코발트는 "초점이 맞은 곳"에만.**
색수차 시안/마젠타는 "아직 정리되지 않은 상태"를 표현할 때만 잠깐 쓴다 (정상 UI에는 금지).

| 토큰 | 라이트 | 다크 | 역할 |
|---|---|---|---|
| `--glass` | `#EDF0EF` | `#0D1012` | 배경 (렌즈 유리 가장자리의 회녹색) |
| `--glass-2` | `#E0E6E3` | `#161B1E` | 면, 카드 |
| `--ink` | `#121519` | `#E6ECEA` | 본문 |
| `--ink-2` | `#4C555B` | `#9AA4A8` | 보조 텍스트 |
| `--line` | `#C6CECB` | `#2B3338` | 구분선 |
| `--core` | `#2430E8` | `#8089FF` | **코어 코발트** — CTA, 활성 상태, 심볼 코어 |
| `--ab-c` | `#00A9BD` | `#2FD3E6` | 색수차 시안 (연출 전용) |
| `--ab-m` | `#D9246F` | `#FF5AA5` | 색수차 마젠타 (연출 전용) |

비율 가이드: 유리/잉크 90% · 코어 8% · 색수차 2% 이하.

**웹사이트 적용 (2026-11 개편)**: 라이트 단일 테마. 바탕 `#EDF0EF`(유리), 한 단계 진한 구역 `#E3E8E5`, **흰색 `#FFFFFF`은 "초점이 맞은 면"(패널·카드)에만**, 코어 코발트는 실행 중인 단계·주 버튼·심볼·섹션 머리표의 점처럼 **초점이 맞은 한 지점에만** 쓴다. 어두운 면은 페이지에 한 번(약속 띠, 진단 결과)만 쓴다. 토큰은 `web/src/styles/global.css`.

왜 이 조합인가: SI/ERP 업계는 대부분 "신뢰의 파랑 + 흰 배경 + 악수하는 스톡 사진"을 쓴다.
OptiCore는 파랑을 **넓게 바르지 않고 점으로 찍는다.** 배경을 순백 대신 차가운 회녹색으로 두어 "광학 장비" 느낌을 낸다.

## 4. 타이포그래피

| 역할 | 서체 | 이유 |
|---|---|---|
| 제목·본문 (국문·영문) | **Pretendard Variable** 400–700 | 국내 서비스의 표준에 가까운 서체. 큰 제목에서도 단단하고, 한글·영문·숫자 폭이 고르다 |
| 데이터·라벨 | **IBM Plex Mono** 400/500 | 에이전트 실행 기록, 점수, 기간처럼 "기계가 낸 값"에만 쓴다 |

- Pretendard는 `web/public/fonts/pretendard/`에 직접 올려 쓴다 (OFL). Plex Mono는 Google Fonts.
- 로고 파일(SVG)의 워드마크는 Bricolage Grotesque 그대로 두고, 웹 헤더의 `opticore`는 Pretendard Bold로 쓴다.
- 한글 줄바꿈: `word-break: keep-all` 필수 (단어 중간에서 끊기지 않게).
- 제목 자간 -3% ~ -4.5%, 본문 -1%. 라벨에 대문자·넓은 자간을 쓰지 않는다.
- 2026-11 이전에는 IBM Plex Sans KR + Bricolage 조합이었다. 참고 사이트 비교 뒤 Pretendard로 바꿨다.

## 5. 그래픽 모티프

1. **초점 맞추기 (Focus pull)** — 흐림+색수차 상태에서 선명한 상태로. 히어로, 로딩, 전환 화면에 사용.
2. **초점거리 눈금 (∞ · 5m · 2m · 1m · 0.5m · 0.3m)** — 렌즈 경통의 거리 눈금. 웹사이트 스크롤 위치, 제안서 목차, 슬라이드 진행 표시에 사용. 고객에게 "가까워질수록 핵심에 닿는다"는 흐름.
3. **상태 머신** — `SCAN → FOCUS → BUILD → RUN → SCAN`. 회사의 방법론이자 다이어그램 언어. 제안서·보고서·대시보드에 동일하게 쓴다.
4. **취소선 → 코어 칩** — "견적서_최종_진짜최종.xlsx" ~~취소선~~ → `견적·수주` 칩. Before/After를 보여주는 기본 문법.

5. **초점 표시 (꺾쇠)** — 네 모서리의 짧은 꺾쇠. 에이전트가 지금 하고 있는 단계, 점수판에서 고른 업무처럼 "지금 초점이 맞은 것"에만 건다 (`.focus-mark`).
6. **에이전트가 일하는 장면** — 요청 → 사내 데이터 확인(ERP·문서·메일) → 초안 → 사람 승인. AX를 설명하는 기본 그림. 예시는 항상 "예시"라고 적는다.

웹사이트에서는 2번(초점거리 눈금)과 영문 상태 코드(SCAN·FOCUS…)를 앞에 내세우지 않는다: 고객에게 낯선 용어라는 검토 결과에 따른 것. 한글 단계 이름(진단·설계·구축·운영)을 쓴다.

금지: 악수·회의실 스톡 사진, 지구본+네트워크 선, 보라→파랑 그라데이션, 3D 로봇, 빛줄기·입자 물결 같은 추상적인 "AI 느낌" 이미지.

## 6. 말투 (Voice)

- **구체적으로**: "디지털 혁신" 대신 "월말 마감 4일 → 1일".
- **쉬운 말**: 고객 현업이 쓰는 단어로. "워크플로 오케스트레이션" 대신 "결재 순서 자동화".
- **짧게, 능동으로**: "~을 통해 ~를 제공합니다" 금지. "~합니다".
- **약속은 조건과 함께**: 각 단계의 "다음으로 가는 조건"을 항상 말한다.

| 이렇게 | 이렇게 쓰지 않음 |
|---|---|
| 프로그램은 다섯 개인데 서로 대화를 안 할 때 | 이기종 시스템 간 데이터 사일로 해소 |
| 2주마다 실제로 동작하는 버전을 보여드립니다 | 애자일 방법론 기반 고객 중심 개발 |
| 중요한 결정에는 사람의 승인 단계를 둡니다 | 안전하고 신뢰할 수 있는 AI |
