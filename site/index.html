프로젝트는 네 개의 상태만 가집니다.

각 상태에는 끝나는 조건이 정해져 있습니다. 조건을 통과해야 다음 상태로 넘어가고, 운영 데이터는 다음 진단의 출발점이 됩니다.

RUN → SCAN · 운영에서 쌓인 데이터로 다음 개선을 진단합니다

    2 m · 서비스

    네 개의 렌즈, 하나의 초점.

    문제에 맞는 렌즈를 고릅니다. 대부분의 회사는 둘 이상이 필요하고, 그래도 계약 창구와 책임자는 한 명입니다.

    SI

    시스템 통합

    따로 노는 프로그램들이 같은 데이터를 보게 만듭니다. 쇼핑몰, 회계, 물류, 그룹웨어 사이의 복사·붙여넣기를 없앱니다.

    API 연동데이터 이관레거시 현대화

    이럴 때프로그램은 다섯 개인데 서로 대화를 하지 않을 때.

    ERP

    ERP 구축

    회사 업무 순서에 맞춘 ERP를 만듭니다. 검증된 오픈소스와 패키지를 먼저 비교하고, 꼭 필요한 부분만 새로 개발합니다.

    OdooERPNext패키지 커스터마이징자체 개발

    이럴 때월말 마감이 며칠씩 걸리고 숫자가 부서마다 다를 때.

    AX

    AI 전환

    사내 문서와 데이터에 연결된 AI 에이전트를 업무 흐름 안에 넣습니다. 중요한 결정에는 항상 사람의 승인 단계를 둡니다.

    업무 에이전트문서 검색승인 워크플로MCP 연동

    이럴 때같은 질문과 같은 서류 작업이 매일 반복될 때.

    SaaS

    구독형 모듈

    구축 프로젝트에서 반복해서 검증된 기능을 바로 쓸 수 있는 서비스로 제공합니다. 구축 없이 시작하고, 필요하면 맞춤으로 확장합니다.

    예시: 전자결재예시: 재고예시: 매입 자동 수집

    이럴 때지금 당장 한 가지 문제만 빨리 풀고 싶을 때.

    1 m · 원칙

    코드 한 줄 전에 지키는 여섯 가지.

    오티코어의 모든 엔지니어와 AI 에이전트가 같은 원칙으로 일합니다. 그래서 누가 맡아도 결과가 같습니다.

    P-STATE

    숨은 상태를 꺼냅니다

    로딩 중인데 에러도 보이는 화면은 상태가 숨어 있다는 신호입니다. 상태와 전이를 표로 드러내서 사용자, 개발자, AI 모두가 읽을 수 있게 합니다.

    idle → loading → (success | error)
    P-OSS

    먼저 찾아보고 만듭니다

    처음 보는 기능은 맨땅에 짓지 않습니다. 관련 오픈소스를 찾아 접근 방식을 비교한 뒤에 시작합니다.

    search → compare → decide → build
    P-TRIAGE

    버그는 점수로 다룹니다

    빈도와 심각도를 곱해 5 미만이면 기록만 하고, 아무도 요청하지 않은 미래를 위해 설계하지 않습니다.

    2 × 2 = 4이슈로 기록
    P-CLOSE

    끝까지 갑니다

    중간에 "계속할까요?"를 묻지 않습니다. 무언가를 지우기 전에만 확인하고, 마지막 보고는 핵심부터 쉬운 말로 씁니다.

    confirm only before: delete
    P-CI

    느린 빌드를 숫자로 봅니다

    최근 150번의 CI 실행을 대기, 셋업, 실행 시간으로 나누어 가장 느린 작업 다섯 개를 먼저 보고합니다. 고치는 건 보고 다음입니다.

    queue | setup | run (seconds)
    P-REBUILD

    처음부터라면 무엇을 남길까

    큰 변경 전에 같은 목표로 오늘 다시 시작한다고 가정합니다. 남길 것, 버릴 것, 다시 만들 것을 나눠서 결정합니다.

    keep / drop / rebuild

    0.5 m · 에이전트 입구

    사람이 보는 사이트, AI가 읽는 사이트.

    고객의 AI 비서가 먼저 우리를 찾아오는 시대입니다. 오티코어가 만드는 시스템은 사람용 화면과 함께 에이전트가 읽고 쓸 수 있는 입구를 처음부터 갖춥니다. 이 사이트도 그렇게 만들었습니다.

    • llms.txt회사 소개, 서비스, 연락 방법을 AI가 읽기 좋은 한 장으로.
    • 명시적 상태프로젝트 상태를 SCAN · FOCUS · BUILD · RUN 그대로 노출.
    • 진단 API아래 진단과 같은 질문을 에이전트가 JSON으로 보낼 수 있게.
